## 二、视频的量化档位结论表（口播版）

| 格式 | 视频原话要点 |
|---|---|
| **BF16 / 完整版** | 最接近官方。约 60 GB 体积，再加文本编码器、VAE、中间激活和 ComfyUI 开销；适合它的是 H100 / RTX PRO 6000。"普通一张 5090 32G 显然放不下"，offload 也只会换来极慢速度 → **消费级实际选择面很小** |
| **INT8** | 权重压到 8bit，体积和显存明显下降，同时保持接近完整版的质量 → **4090/5090 这类消费级旗舰的最佳终点方案** |
| **NVFP4** | 50 系（Blackwell）专属格式，靠 Blackwell 硬件能力用更低显存换相对不错的速度 |
| **W4A8** | 4bit 压缩，**对 30/40 系老架构更友好**；50 系也能跑，只是 NVFP4 更快。适合 12–16 GB 显存。视频自己承认："和原版相比，能跑、速度也还行，但**生成质量有较大损失**，量力而行" |
| **GGUF** | 不是单一模型而是一套封装/量化路线（Q4/Q5/Q6/Q8…）。Q4 是平衡版本。**UP 明确说不会把 GGUF 放第一推荐**：它更依赖 CPU+内存卸载和通用量化执行，对速度和兼容性有要求，数据搬运效率不如 W4A8 / INT8 / NVFP4 这些针对 CUDA 优化过的版本。但"你可以根据自己的硬件和习惯选" |
| **NF4** | 8 GB 显卡能玩，但极慢 + 质量损失巨大 → **普通玩家不建议**，更建议云部署或直接用官方 API |
| **剪枝版（pruned）** | 不是第二种精度，而是原始模型剪掉一部分不重要权重让模型变小，再做成 INT8 / NVFP4 / W4A8 / GGUF。体积对照（口播）：**剪枝 21G / INT8 34G / BF16 60G** |

**视频给出的按硬件推荐：**

| 硬件 | 视频推荐 |
|---|---|
| N 卡 24G+（3090/4090/5090） | **优先剪枝版 INT8**（不必强求 BF16/完整 INT8） |
| 50 系非旗舰 | **NVFP4** |
| 16 GB（4070TiS / 4080 等） | **优先 W4A8**；跑不稳再退到 GGUF 的 Q4 档 |
| 12 GB（3060 12G / 4070 12G / 4070S） | **优先 GGUF Q4**；部分 50 系可试 NVFP4 + 内存卸载 |
| 8 GB | NVFP4 或更小的 GGUF，"能跑但不建议作为主力生产方式" |
| AMD 24G+ | 试 INT8，或 GGUF；**16G 左右优先 GGUF Q4 档更稳妥**；注意 ROCm 环境与节点兼容 |
| Intel Arc | XPU + GGUF；16G+ 用 Q4 档，12G 从 Q4 开始；生态不成熟 |
| Apple M 芯片 | ComfyUI + **MLX 专用格式**（不能照抄 N 卡路线）；统一内存 ≠ 独显，**24G 起步做实验、32G 入门、48G+ 更顺** |

**结尾三步选型法：** ① 定位硬件品牌（表按 NVIDIA / AMD / Intel / Apple 分区）→ ② 找到自己的显存档位 → ③ 看"最佳推荐版本"这一列（= 综合显存兼容性、运行速度、使用难度后的推荐，**不是画质最高**）。UP 强调别一上来把所有版本都下一遍。

## 三、视频讲得对、且与社区/官方口径一致的部分

1. **BF16/完整版与消费级无关**：Comfy-Org 里 bf16 FL2VA 单变体 66.3 GB，剪枝 bf16 也要 40 GB 级 —— 视频说"60G、5090 放不下"成立。
2. **体积链 21G / 34G / 60G**：对应剪枝 int8（19.53 GiB）、完整 int8（34 GB）、完整 bf16（66.3 GB），基本准（口播的 60G 略低）。
3. **24G+ 首选剪枝 int8**：minimaxh3.app、jxxy、comfyui-wiki 三处口径一致（剪枝 int8 DiT 19.53 GiB + NVFP4 文本编码器 14.61 GiB ≈ 34 GiB）。
4. **NVFP4 是 Blackwell 专属**：Ada（30/40 系）上 NVFP4 只是"能加载但走模拟、没有加速收益"，官方仓库也明确写"30/40 系请勿下载 nvfp4 文件"。
5. **GGUF 依赖 CPU/内存卸载、效率不如 CUDA 原生量化**：与 smeltcore 对 4070 SUPER 的 offload 剖析一致 —— 12G 卡上每步至少 8.7 GiB 要走 PCIe。
6. **剪枝 = AdaLN 剪枝，省约 40% 参数**：与 ComfyUI 官方 day-0 博文（约 40% 调制权重可剪成查找表，总占用 123.6 GB → 42.5 GB）完全对应。
7. **8G 不建议本地、建议 API/云**：合理。
8. **"别忘文本编码器 + Video VAE + Audio VAE；当前仓库没有就回官方仓库下"**：这条很实用，缺音频 VAE 的典型症状是视频正常但没声音。
9. **FL2VA（文生/首尾帧）vs Ref2VA（图/音/视频参考）**：正确。
10. **别一次把全部版本都下载**：正确，单文件动辄 10–20 GB。

## 四、视频**没讲**、但实操一定会撞上的事（我补 7 条）

1. **本地硬上限是 768p**（短边 768，最大 1344×768，最小 384p）。原生 2K 走托管的 `H3-Regenerate-2K`，没有开源。视频全程没提分辨率上限 —— 如果你交付物要 2K，本地这条线根本不成立。
2. **许可地域限制**：H3 社区许可排除**美国 / 欧盟 / 英国 / 韩国**，且条款覆盖输出物与衍生模型。国内自用没问题，对外商用要留意。
3. **CUDA 必须 13**：cu128 的 PyTorch 会**静默**关掉 int8-convrot 快速路径（不报错，只是慢约 3 倍）。视频完全没提。
4. **真正卡住 12–16G 卡的是主机而不是显卡**：32 GB 内存是下限（必须配 `--disable-pinned-memory`，否则加载阶段会被 OOM kill），64 GB 才顺；官方 Diffusers 的"INT8 + CPU offload + 960×544 小画布"参考配方**甚至要 ~75 GB 主机内存**。权重还必须放 NVMe —— 内存不足时硬盘会进入采样循环。
5. **加速方案完全缺位**：Turbo LoRA（4 步只当草稿、6–8 步成片）、SageAttention、KJNodes 的 `H3 Low VRAM Attention` / `Chunk FeedForward`（输出与原模型一致，可延后降量化）。**换 Turbo + Sage 省下的时间，通常比换量化档更多**。
6. **GGUF 有两个隐性成本**：① 需要额外的加载器节点包（8 月初原生 ComfyUI-GGUF 的白名单里没有 H3，issue #471 当时还开着；到 9 月中旬已有 2080Ti 实测用 `UnetLoaderGGUF` 跑通，说明中间已支持）；② H3 去噪器隐藏维 2688 不能被 256 整除，标着 `Q4_K_M` 的文件内部多半实际是 Q4_0/Q4_1 —— **按文件体积挑，不要按后缀挑**。
7. **两个省显存的现成技巧**：社区 fp8mix 视频 VAE（2.60 GiB）+ bf16 音频 VAE（289 MiB）比官方组合省约 2.5 GiB，12–16 GB 卡值得换；另有 148 MiB 的 Ref Patch 能让 FL2VA 权重部分模拟 Ref2VA，想要参考能力又心疼显存时可用。

## 五、与视频口径**不一致**、需要自己权衡的 4 处

1. **12 GB 档：视频推"GGUF Q4"，我上轮推"剪枝 int8 + NVFP4 文本编码器 + 强卸载"。**
   - 两条都能跑。GGUF Q4 更省显存、但吃额外节点包与 CPU 卸载；剪枝 int8 免节点包、质量更好，但 32 GB 内存 + NVMe 是硬前提（4070 SUPER 的实际配方就是 864×480 / 124 帧 / 20 步）。
   - 建议：**先按视频的 GGUF Q4 跑通，再试剪枝 int8 对比一秒一帧的画质**，别先信任何一方。
2. **16 GB 档：视频推 W4A8（≈ 社区 INT4 / 混合 INT4-INT8，11.3 / 15.5 GB），并承认"质量损失较大"。**
   - 16 GB 其实还有一条"剪枝 int8 + 轻卸载，配 Turbo 8 步"的路，质量明显更好，代价是慢。
   - 取向清楚：**要画质 → int8 + Turbo；要速度/省心 → INT4 或 mixed INT4-INT8**。
3. **主机内存口径不统一**：32 GB（能跑，必须关 pinned memory）/ 64 GB（顺）/ ~75 GB（官方 diffusers int8+offload 参考配方）。视频只在讲 BF16 时提了一句"系统内存"，容易让人以为显存够就行。
4. **口播里出现的 "U16G" 我无法确认**（转写存疑）：社区 GGUF 里与它最接近的是 Unsloth 的动态量化（UD）系列。**以 UP 表格原文为准，不要按我的转写去下文件。**

## 六、落到你那两张卡的最终结论

| | RTX 4070 Super 12G（192-bit / 504 GB/s） | RTX 4070 Ti Super 16G（256-bit / 672 GB/s） |
|---|---|---|
| 视频推荐 | GGUF Q4 档（约 10.6 GiB）+ 小文本编码器 | W4A8（≈ INT4 / mixed INT4-INT8，11.3–15.5 GiB） |
| 我的补充推荐 | 剪枝 int8（19.5 GiB）+ **NVFP4 AWQ 文本编码器**（14.6 GiB，Ada 上只当存储格式，比 int8 版省 10.7 GiB） | 画质优先：剪枝 int8 + 轻卸载 + Turbo；速度优先：mixed INT4-INT8 |
| 首次参数 | 864×480（0.4 MP）/ 124 帧 / 5 秒 | 0.4–0.5 MP；配 Turbo 可摸 768p 短边 |
| 主机前提 | **32 GB 内存 + NVMe + `--disable-pinned-memory`** | 64 GB 内存更顺 |
| 预期 | 5 秒草稿 6–10 分钟（内存只有 16 GB 会掉到 20–29 分钟） | 2–7 分钟 |
| 共同 | Turbo LoRA + SageAttention 必装；只有 2K 交付就绕开本地走 API | 同左 |

一句话：**视频的"看显存档位选格式"框架是对的，可以直接照它那张表起步；但你那两张卡的真实瓶颈是内存与硬盘，而且本地只有 768p。**
